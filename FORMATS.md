# Original file formats

All layouts begin as **UNKNOWN**. Offsets and fields enter this file only after local file inspection and an independent check. Raw game bytes and decompiler output belong in ignored private research.

### IPF executable-dispatch follow-up

**VERIFIED (local Ghidra decompilation and decoded corpus, 2026-10-09):** one inspected type-1 record begins with a 32-bit opaque word, a length-prefixed byte string, and a selector word. The executable dispatches selector 1 to three 32-bit words and selector 2 to five; both then reach common fixed fields: a separate three-word block, one word, two bytes, two three-word records, and two two-word records. The handler then reads three nested count tables with 24-byte, 2-byte, and 32-byte inner rows. These values remain opaque. A recursive reader walks all siblings in all 71 common-family IPFs: 1,044 type-1 records (selectors 0: 150, 1: 894), 262 type-3 containers, maximum depth 3, and zero trailing bytes in each file. Selector 2 is source-supported but absent from this family. The four outlier root families remain **UNKNOWN**.

**VERIFIED (decoded local corpus, 2026-10-09):** the sole third-level type-3 container has three declared children and begins with a selector-1 type-1 record; all three children are traversed by the full-tree reader.

`blur-formats::read_ipf_type1_variant1_prefix`, `read_ipf_type1_continuation_prefix`, and `read_ipf_type1_variant2_prefix` expose the fixed fields; `read_ipf_type1_opaque_payload` consumes the selected prefix, common fields, and count tables after the preceding selector word. It reports spans and counts only, not row meanings.

**VERIFIED (decoded local corpus, 2026-10-08/09):** the four IPFs outside the common masked-header family each expose one root type-3 record. Their count/type words begin at offset 4; three decode as big-endian and one as little-endian. Applying that observed word order to the following type-3 prefix bounds its opaque word, length-prefixed name, and child-count word in all four, and all four name spans are valid UTF-8. A bounded prefix walk recognizes all 36 declared children of `shapes.ipf` as selector-1 type-1 records with valid UTF-8 names under the root's big-endian word order. **VERIFIED (decoded local corpus, candidate-prefix/count reconciliation):** `controller.ipf` has 25 candidate descendants (8 type 3, 17 type 1), `icon_sheet.ipf` has 141 (8 type 3, 133 type 1), and `shop_icons_main.ipf` has 27 (5 type 3, 22 type 1); each recursively reconciles its root and all nested child counts, with no unclaimed candidate prefixes. None of these count reconciliations proves independent leaf extents. **HYPOTHESIS:** candidate payload ends at the next matching prefix (or EOF); these candidate extents and the executable's payload semantics are not established. No broader payload rule is inferred.

**VERIFIED (decoded-payload byte scan, 2026-10-09):** candidate readable labels occur in each outlier: `shapes.ipf` includes `mine`, `barge`, `shunt`, `shock`, `perk_nitro`, `perk_shield`, `repair`, and geometric-name strings such as `quarter_circle`; `shop_icons_main.ipf` includes `nitro_boost`, `extra_shunt`, and `shield`; `icon_sheet.ipf` includes `garage`, `quick_race`, `track`, `pause`, and `steering_wheel`; `controller.ipf` includes `controller`, `controllers`, `circle`, and `square`. This is a raw ASCII-run scan only: it does not establish NUL termination, record membership, field meanings, or asset behavior.

**HYPOTHESIS (decoded local `shapes.ipf`, 2026-10-09):** 23 of 36 candidate selector-1 leaves fit an exact bounded pattern after the 70-byte candidate prefix: one big-endian group word equal to one, a nonzero row count divisible by three, 24-byte rows containing six finite big-endian float words, and an equally sized big-endian 16-bit index array ending at the next candidate prefix (or EOF). Every candidate index is below the row count. The other 13 leaves are rejected by this narrow probe. This supports a candidate geometry interpretation only; executable dispatch, the meaning of the six words, and whether the arrays are vertices/indices remain **UNKNOWN**. `probe_ipf_shape_mesh_candidates` enforces these checks and is covered by a synthetic fixture and an opt-in all-IPF corpus test.

**VERIFIED (local Ghidra decompilation of Blur.exe and decoded PAK corpus, 2026-10-09):** the generic resource-loading path accepts a first word whose masked upper 16 bits equal 16, then reads a root-record count and dispatches type codes. Type 3 consumes an opaque 32-bit word, a 32-bit-length byte string, and a child count; nested type 3 records recurse, while type 1 records go to a separate leaf handler. In the local corpus, 71 of 75 IPFs match this root family. Their root counts are 1 (65 files), 2 (3), 4 (1), 6 (1), and 10 (1); all have type 3 as the first record. The recursive reader bounds all type-1/type-3 sibling spans and consumes each of the 71 common-family files exactly. The four remaining IPFs also have bounded one-record/type-3 root and first-container prefixes under the locally observed count/type byte orders described above; those containers declare 2, 11, 36, and 117 children, and their first tags are type 1 in three files and type 3 in one. Their trees are not parsed.

**VERIFIED (local Ghidra decompilation and decoded corpus, 2026-10-09):** the inspected recursive-loader entry point tests the common masked root signature before reading root child records. All four outlier root words fail that little-endian mask test, so this particular common-family recursive path does not provide their leaf extents. This excludes only the inspected path; separate outlier consumers remain **UNKNOWN**.

**VERIFIED (local Ghidra decompilation, 2026-10-09):** both inspected executable paths that request or refresh a named resource converge on the same root dispatcher before the recursive type-1/type-3 walk. This excludes those two paths as the source of outlier leaf extents. It does not prove that no other consumer exists, nor identify an alternate handler.
