# All-map playable-race coverage

## Goal and current status

Goal: make every installed race level and every playable route variation loadable and playable as a race. A level directory is not counted as complete merely because its files parse or one route works; each observed variation needs a verified drivable course, valid player start/grid, lap/checkpoint progression, and a race that can be driven to completion. Race-wide systems must be data-driven so each variation uses the same tested runtime.

**Current status (2026-11-05): 0/18 installed race directories verified playable; total playable variation count UNKNOWN.** The Phase 2 Tokyo viewer gate is accepted. `blur-app` shows source-draw candidate geometry with a generic controlled car, optional candidate-surface following, and caller-supplied checkpoint/lap lines. It renders selected named textures and opt-in stream texture previews through source-derived outer-object references; the latter recovered all 18 independently capture-matched Tokyo sample payloads and loaded bounded regions in all 19 installed levels. A LA River region displays a recognizable road segment, but the UV, sampler, shader, and scene coverage do not yet match the original game. `blur-sim` has synthetic-tested vehicle motion and ordered gate detection. No installed configuration has verified road collision, race rules, start/variant selection, handling, or AI; the captured Tokyo geometry and `.levelphysics` paths remain research leads.

The local install contains 19 level directories: 18 race directories (including multiplayer-labelled directories) and one showroom. A directory may contain multiple playable routes or event layouts; their total count has not been verified. All 19 have `.level`, `.levelphysics`, `.levelrender`, and `.levelstream` companion files, and `inspect-track --rendering-details` completed successfully for all 19 directories. “Route sections” below counts bounded child sections in `.levelphysics`; it is not a verified count of race routes. Type-0 mesh output counts are from the existing bounded candidate exporter. Candidate archive/node counts are structural diagnostics, not proof of complete geometry.

## Required milestones

1. **Map bundle and selection:** inventory level identity, companion files, variants, and load errors; let the runtime select a level by stable ID without assuming folder ordering. Stable-ID discovery and structural loading are available through `blur-assets` and `blur-app --level`; complete selected-level rendering and gameplay load errors remain open.
2. **Verified course model for every level:** identify road/surface geometry, coordinate transforms, course bounds, and collision representation from evidence. Keep candidate geometry tagged as candidate until visually and physically checked against the original.
3. **Race setup per level:** establish legal start/grid poses, route direction, checkpoints, lap line, and respawn bounds. Verify every configuration, including multiplayer variants, separately.
4. **Shared playable race loop:** progress-core contract is implemented in `blur-sim` and tested with synthetic events; it is not yet connected to geometry or gameplay. Still required: deterministic car control/handling, collision and checkpoint detection, camera, start/finish state, and a complete human-driveable run on each configuration. Add bots only after the basic human race loop is reliable. See `docs/RACE_LOOP.md`.
5. **Coverage gate:** automated load/validation for every installed race level, plus at least one complete captured playthrough per level/configuration. No level is marked playable based only on a successful file parse.

The original project phase plan places renderer parity before handling and the race loop. This all-map goal depends first on resolving course semantics/data per level; preserve that sequence rather than treating the accepted single-scene Phase 2 viewer as a playable race.
